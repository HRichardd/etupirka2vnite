# Etupirka → Vnite 迁移助手

把 **Etupirka** 记录的 galgame 游玩时长搬进 **Vnite**。

Etupirka 会老老实实记下你每天玩了多久，却没有任何导出功能。这个小工具读取它的
`user.db`，把每条记录变成 Vnite 能直接导入的 JSON —— **点一下「复制」，切到 Vnite 粘贴保存**，
就迁完了。

> 只支持 Windows。运行时**零第三方依赖**（Python 标准库 + tkinter）。
> 不想装 Python 就直接下 [Releases](../../releases) 里的发布包，解压即用。

---

## 为什么不能自动导入

Vnite 的数据是 PouchDB(LevelDB)，内部文档结构随版本变化，直写有坏库风险。
而它「游玩时间编辑器」里明确提供了 **从剪贴板导入** —— 这是官方通道，跨版本稳定，
且完全不动它的数据库。

这个工具选择了后者：**只读你的 Etupirka 库，只往剪贴板写文本。**

Etupirka 的 `user.db` 全程以只读方式打开，不会被修改，也不会留下 journal 文件。

## 快速开始

### 1. 拿一份程序

到 [Releases](../../releases) 下载任一形态，**两者功能完全相同**，挑一个就行：

| 下载 | 形态 | 适合 |
|---|---|---|
| `etupirka2vnite-<版本>-win64.zip` | 文件夹版（onedir） | **推荐**。启动即时，不挑环境 |
| `etupirka2vnite-<版本>-win64-onefile.zip` | 单文件版（onefile） | 只想要一个 exe，双击即用 |

**文件夹版**：解压后双击里面的
```
etupirka2vnite\etupirka2vnite.exe
```
> 整个文件夹要一起保留，exe 依赖同目录下的运行库文件。

**单文件版**：解压出那个 `etupirka2vnite.exe` 就能直接双击。
> 它每次启动会先把自身解压到 `%TEMP%` 再运行，所以启动比文件夹版慢几秒；
> 若所在环境限制临时目录写入（受限沙箱、部分企业管控策略），可能启动失败——
> 那种情况下请改用文件夹版。

两种形态都可以放桌面：右键 exe → 发送到 → 桌面快捷方式。配置存在 exe 同级目录，
把程序（文件夹版则连同整个文件夹）一起搬走，设置和进度就跟着走。

### 2. 选数据源

点「**选择目录…**」选中 Etupirka 所在的文件夹（里面要有 `user.db`），
或者用「**选择 user.db…**」直接指定那个文件。

选过一次就会记住，下次打开自动加载。

### 3. 逐条复制进 Vnite

```
① 在本工具里点某条右边的「复制」
② 切到 Vnite，打开该游戏的「游玩时间」编辑器
③ 点右上角 ☰ 菜单 → 「从剪贴板导入」
④ 点「保存」→ 弹出确认警告 → 确认
```

复制过的条目左边会打 **✓**，底部显示 `已迁移 1 / 3 条`，关掉工具再打开也还在。

## 功能

| 功能 | 怎么用 |
|---|---|
| **复制导入数据** | 点行尾「复制」/ 双击该行 / 右键「复制导入数据」 |
| **复制游戏名** | 右键「复制游戏名」/ 详情面板的「复制名」按钮 / `Ctrl+C`。便于在 Vnite 里搜索或手动添加游戏 |
| **重命名** | 右键「重命名为…」。给未识别条目起名，也可以**修正**读来的原标题。名字留空并确定 = 清除别名 |
| **标记为已迁移 / 未迁移** | 右键菜单。手工纠正进度，不会影响已复制的内容 |
| **查看原始 JSON** | 右键菜单。想手动复制或检查内容时用 |
| **导出** | 顶部「导出…」按钮，产出 4 个文件（见下） |
| **筛选** | 顶部右侧三个单选：全部 / 未迁移 / 未识别 |

### 「未识别」是怎么回事

Etupirka 里**被删掉的游戏条目**，每日时长还留在库里，但游戏名没了
（Etupirka 的 uid 是随机 16 位，物理上不可逆）。这类记录会显示成 `未识别-01`、`未识别-02`……

如果你能想起来是哪部作品，右键「重命名为…」写上去即可，列表、导出、复制的 JSON 都会跟着更新。
起过的名字存在 `aliases.json`，下次打开还在。

## 导出的 4 个文件

点「导出…」后，在你选定的目录里生成：

| 文件 | 内容 |
|---|---|
| `etupirka-汇总.csv` | 按游戏的时长汇总（含起止日期、启动路径、迁移状态）。Excel 可直接打开 |
| `etupirka-每日明细.csv` | 逐日明细，一行一天 |
| `etupirka-raw.json` | 完整原始转储（**时长单位是秒**，与 Etupirka 源数据一致） |
| `report.txt` | 给人读的报告：统计、提醒、被丢弃的记录、别名表、未识别清单、还没迁移的清单 |

导出**只覆盖自己生成的那 4 个文件**，同一个目录里你放的其它东西不会被删。

## 运行时产生的文件

全部写在 **exe 同级目录**（若该目录不可写，自动回退到 `%APPDATA%\etupirka2vnite\`，
程序会在状态栏告诉你实际位置）：

| 文件 | 内容 |
|---|---|
| `settings.json` | 记住的数据源、最近 5 个路径、上次导出目录 |
| `aliases.json` | 你给未识别条目起的名字 |
| `progress.json` | 哪些条目已经复制过导入数据 |
| `error.log` | 只在程序真的出错时才出现 |
| `out/` | 默认导出目录 |

**换机器 = 把这 4 个文件跟 exe 一起复制过去。** 配置立刻恢复：数据源、别名、迁移进度全在。

## 常见问题

**Q：粘到 Vnite 里没反应 / 报错？**
先在本工具里点「复制」，再去 Vnite 按粘贴。剪贴板内容在**关闭本工具后依然保留**，
所以可以一次复制好几条再慢慢粘。

**Q：导入是覆盖还是累加？**
**覆盖**。Vnite 保存时会整体替换该游戏的 `timers` 和 `dailyPlayTimes`。
建议在 Vnite 还没自己记录这些游戏之前导入。如果你的 Vnite 已经记过时长，导入会把它顶掉。

**Q：导入后 Vnite 的「最近游玩」列表没更新？**
已知限制，尚未实测确认。Vnite 那个字段是从精确时间段（`timers`）算出来的，
而 Etupirka 只有「每天玩了多久」，没有起止时刻，这类数据进的是「日级记录」。
好处是它不会被伪造成假时间段、污染小时分布图；代价可能就是「最近游玩」不参与。

**Q：数据读到的对吗？怎么确认它读的是哪个库？**
顶部「Etupirka 目录」那行就是当前数据源。也可以跑自检：

```
etupirka2vnite.exe --selfcheck
```
在 exe 旁生成 `selfcheck.txt`，写明程序目录、配置目录、各配置文件位置、是否可写、
读到的数据源与条目统计。

**Q：Windows 弹窗说「已保护你的电脑」？**
exe 没有代码签名。点「更多信息 → 仍要运行」。

**Q：exe 启动快吗？为什么发布包是一个文件夹而不是单个 exe？**
发布包用的是 **onedir** 模式（一个文件夹），启动是即时的。

两者都能正常工作，区别只在启动方式：

| | 单文件 `--onefile` | 文件夹 `--onedir`（本发布包） |
|---|---|---|
| 分发形态 | 一个 exe | 一个文件夹 / zip |
| 启动 | 每次先自解压到系统临时目录 | 直接启动，无解压 |
| 临时目录权限 | 依赖（受限环境会启动失败） | 不依赖 |
| 杀软误报 | 相对容易 | 相对少 |

单文件版需要先把自己解压到 `%TEMP%\_MEIxxxxxx` 再运行，所以启动慢一些；
若所在环境限制临时目录写入（例如受限沙箱、部分企业管控策略），它会解压失败并报错退出。
onedir 完全不做自解包，因此启动更快也更稳，代价是分发时要给整个文件夹（压成 zip 即可）。

**Q：提示「这个目录里没有 user.db」？**
Etupirka 是绿色软件，`user.db` 和 `Etupirka.exe` 放在一起，选那个文件夹。
如果你只备份了 `user.db`，用「选择 user.db…」直接指它。

## 从源码运行

```
python etupirka2vnite.py                    # 启动界面
python -m app.etupirka_db --db <路径>        # 命令行打印条目清单（不写文件）
python -m app.etupirka_db --db <路径> --json # 机器可读
```

只需要 Python 3 自带的标准库（`tkinter` / `sqlite3`）。
开发与验证环境：**Windows + Python 3.14**。

## 跑测试

```
python -m unittest discover -s tests -t .
```

**269 项**单元测试，覆盖数据读取、载荷校验、剪贴板、进度持久化、
别名、导出、界面交互、打包自检。

## 重新打包

```
build.bat
```

会按需通过 pip 安装 PyInstaller，然后**一次产出两种形态**：

```
dist\onedir\etupirka2vnite\                        文件夹版程序目录
dist\onefile\etupirka2vnite.exe                    单文件版 exe
dist\etupirka2vnite-<版本>-win64.zip               文件夹版发布包（直接传 Release）
dist\etupirka2vnite-<版本>-win64-onefile.zip       单文件版发布包（直接传 Release）
```

版本号自动取自 `app\__init__.py` 的 `__version__`（同时写进 exe 的文件属性）。
想换图标就把一个 `.ico` 命名为 `etupirka2vnite.ico` 放进本目录，重跑即可。

单独构建某一形态：

```
python -m PyInstaller etupirka2vnite.spec --noconfirm                          # onedir
set ETUPIRKA_ONEFILE=1 && python -m PyInstaller etupirka2vnite.spec --noconfirm # onefile
```

## 已知限制

- **只做 Etupirka → Vnite**，不支持其它来源或目标
- **只有 Windows**（剪贴板用 Win32 API，Etupirka 本身也只有 Windows 版）
- **导入是替换而非合并**（Vnite 的行为决定）
- **不逆向 uid**：Etupirka 的条目 ID 是随机生成的，被删掉的游戏名找不回来
- **无法设置 Vnite 的「最近游玩」**，原因见常见问题
- 不联网，不做多语言
